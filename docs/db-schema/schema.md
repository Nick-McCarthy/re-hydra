# re-hydra database schema

Status: schema of record for migrations `001` through `011`. Runnable SQL lives in `apps/api/src/db/migrations/` (applied via `npm run api:migrate`). Product behavior: [architecture.md](../architecture.md). What is next: [roadmap.md](../roadmap.md). Why the tables are shaped this way: [schema-reasoning.md](schema-reasoning.md).

Target: PostgreSQL 16+. UUIDs are generated by the API (`gen_random_uuid()` is fine as a default). Timestamps are `timestamptz`. Payload bytes live in the object bucket (`BLOB_STORE=s3`). `blob_objects` is the postgres fallback when `BLOB_STORE=postgres`. The `blobs` row stays the catalog either way.

Enums are listed as PostgreSQL `CREATE TYPE` values. Application code should treat them as closed sets.

```text
blobs  (content-addressed; referenced by hash from other tables)
```

## Tables

### `blobs`

Registry of immutable object-store objects. Other tables reference `sha256`; they do not store bytes.

```sql
CREATE TABLE blobs (
  sha256       bytea PRIMARY KEY CHECK (octet_length(sha256) = 32),
  size_bytes   bigint NOT NULL CHECK (size_bytes >= 0),
  content_type text NOT NULL,
  created_at   timestamptz NOT NULL DEFAULT now()
);
```

### `users`

```sql
CREATE TABLE users (
  id            uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  email         citext NOT NULL UNIQUE,
  display_name  text NOT NULL,
  password_hash text CHECK (password_hash IS NULL OR length(password_hash) > 0),
  created_at    timestamptz NOT NULL DEFAULT now(),
  last_seen_at  timestamptz
);

CREATE INDEX users_display_name_trgm
  ON users USING gin (display_name gin_trgm_ops);
```

Requires `citext` and `pg_trgm`.

`password_hash` is a scrypt string. Null means the account has no password yet. Migration `010` drops `magic_link_tokens`.

### `sessions`

Bearer sessions issued after sign-up, sign-in, or a password change.

```sql
CREATE TABLE sessions (
  id            uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id       uuid NOT NULL REFERENCES users (id) ON DELETE CASCADE,
  token_hash    bytea NOT NULL UNIQUE CHECK (octet_length(token_hash) = 32),
  expires_at    timestamptz NOT NULL,
```

### `access_tokens`

A second credential for the CLI. The browser still uses a password session. The raw token is returned once at creation and only its sha256 hash is stored. Changing a password revokes sessions and leaves these rows alone. `hydra logout` forgets the copy on that machine and does not set `revoked_at`.

```sql
CREATE TABLE access_tokens (
  id           uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id      uuid NOT NULL REFERENCES users (id) ON DELETE CASCADE,
  label        text NOT NULL CHECK (length(label) >= 1 AND length(label) <= 80),
  token_hash   bytea NOT NULL UNIQUE CHECK (octet_length(token_hash) = 32),
  created_at   timestamptz NOT NULL DEFAULT now(),
  last_used_at timestamptz,
  revoked_at   timestamptz
);

CREATE INDEX access_tokens_user_id_idx ON access_tokens (user_id)
  WHERE revoked_at IS NULL;
```

### `chunks`

Unit of work and lease lock. Lease columns live on this row so checkout is one conditional update.

```sql
CREATE EXTENSION IF NOT EXISTS btree_gist;

CREATE TABLE chunks (
  id                   uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  project_id           uuid NOT NULL REFERENCES projects (id) ON DELETE CASCADE,
  binary_id            uuid NOT NULL REFERENCES binaries (id) ON DELETE CASCADE,
  name                 text NOT NULL,
  address              bigint NOT NULL CHECK (address >= 0),
  size                 integer NOT NULL CHECK (size > 0),
  -- half-open range [address, address + size)
  addr_range           int8range GENERATED ALWAYS AS
                         (int8range(address, address + size, '[)')) STORED,
  bytes_sha256         bytea NOT NULL REFERENCES blobs (sha256),
  pseudocode_sha256    bytea NOT NULL REFERENCES blobs (sha256),
  disassembly_sha256   bytea NOT NULL REFERENCES blobs (sha256),
  language_override    text,                  -- null → project.language
  state                chunk_state NOT NULL DEFAULT 'open',

  -- lease (null when not leased / not validating)
  lease_user_id        uuid REFERENCES users (id),
  lease_token          uuid,
  lease_expires_at     timestamptz,
  hold_started_at      timestamptz,

  -- pinned context
  type_revision_id     uuid REFERENCES type_revisions (id),
  current_match_id     uuid,                  -- FK added after matches exists
  best_attempt_id      uuid,                  -- FK added after attempts exists
  fuse_parent_id       uuid REFERENCES chunks (id),

  created_at           timestamptz NOT NULL DEFAULT now(),
  updated_at           timestamptz NOT NULL DEFAULT now(),

  CHECK (address + size > address),           -- no overflow of the span
  CHECK (
    (state = 'open' AND lease_user_id IS NULL
                    AND lease_token IS NULL
                    AND lease_expires_at IS NULL
                    AND hold_started_at IS NULL)
    OR
    (state = 'leased' AND lease_user_id IS NOT NULL
                      AND lease_token IS NOT NULL
                      AND lease_expires_at IS NOT NULL
                      AND hold_started_at IS NOT NULL)
    OR
    (state = 'validating' AND lease_user_id IS NOT NULL
                          AND lease_token IS NOT NULL
                          AND hold_started_at IS NOT NULL)
    OR
    (state IN ('matched', 'stale', 'blocked')
       AND lease_user_id IS NULL
       AND lease_token IS NULL
       AND lease_expires_at IS NULL)
  ),
  CHECK (fuse_parent_id IS NULL OR fuse_parent_id <> id)
);

-- Identity of a function body inside a binary
CREATE UNIQUE INDEX chunks_binary_bytes_addr
  ON chunks (binary_id, bytes_sha256, address, size);

-- No overlapping address spans inside one binary
ALTER TABLE chunks ADD CONSTRAINT chunks_no_overlap
  EXCLUDE USING gist (binary_id WITH =, addr_range WITH &&);

CREATE UNIQUE INDEX chunks_lease_token_uidx
  ON chunks (lease_token)
  WHERE lease_token IS NOT NULL;

CREATE INDEX chunks_project_state_addr_idx
  ON chunks (project_id, state, address);

CREATE INDEX chunks_lease_expiry_idx
  ON chunks (lease_expires_at)
  WHERE state = 'leased';

CREATE INDEX chunks_lease_user_idx
  ON chunks (lease_user_id)
  WHERE lease_user_id IS NOT NULL;

CREATE INDEX chunks_fuse_parent_idx
  ON chunks (fuse_parent_id)
  WHERE fuse_parent_id IS NOT NULL;

CREATE INDEX chunks_binary_open_idx
  ON chunks (binary_id)
  WHERE state = 'open';
```

Checkout (product plan):

```sql
UPDATE chunks
SET state = 'leased',
    lease_user_id = $user,
    lease_token = $token,
    lease_expires_at = now() + make_interval(hours => $lease_hours),
    hold_started_at = COALESCE(hold_started_at, now()),
    updated_at = now()
WHERE id = $id
  AND state = 'open'
  AND lease_user_id IS NULL
  AND fuse_parent_id IS NULL   -- members are not independently leaseable
RETURNING *;
```

A fused parent is itself a `chunks` row whose `addr_range` covers the members. Members set `fuse_parent_id`, move to a non-leaseable state path, and release their `addr_range` occupancy so the parent can satisfy `chunks_no_overlap` (see [schema-reasoning.md](schema-reasoning.md)). Members are never open for checkout.

### `jobs`

matchd work queue. Stage A/B may keep this in Postgres; claim with `FOR UPDATE SKIP LOCKED`.

```sql
CREATE TABLE jobs (
  id                 uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  project_id         uuid NOT NULL REFERENCES projects (id) ON DELETE CASCADE,
  chunk_id           uuid NOT NULL REFERENCES chunks (id) ON DELETE CASCADE,
  attempt_id         uuid REFERENCES attempts (id) ON DELETE CASCADE,
  proposal_id        uuid,                    -- FK added after type_proposals
  kind               job_kind NOT NULL,
  state              job_state NOT NULL DEFAULT 'queued',
  priority           smallint NOT NULL DEFAULT 100,
  -- lower number = sooner; interactive uses e.g. 10, revalidation 100
  toolchain          jsonb NOT NULL,
  language           text NOT NULL,
  entry_symbol       text NOT NULL,
  original_sha256    bytea NOT NULL REFERENCES blobs (sha256),
  sources            jsonb NOT NULL,
  -- [{ "path": "candidate.c", "sha256": "…" }, …]  hashes, not inline text
  claimed_by         text,                    -- worker id
  claim_expires_at   timestamptz,
  result             jsonb,
  created_at         timestamptz NOT NULL DEFAULT now(),
  finished_at        timestamptz,
  CHECK (
    (kind = 'interactive' AND attempt_id IS NOT NULL)
    OR
    (kind = 'revalidation' AND proposal_id IS NOT NULL)
  )
);

CREATE INDEX jobs_claim_idx
  ON jobs (priority ASC, created_at ASC)
  WHERE state = 'queued';

CREATE INDEX jobs_claimed_expiry_idx
  ON jobs (claim_expires_at)
  WHERE state = 'claimed';

CREATE INDEX jobs_project_id_idx ON jobs (project_id, created_at DESC);
```

Claim:

```sql
UPDATE jobs
SET state = 'claimed',
    claimed_by = $worker,
    claim_expires_at = now() + interval '2 minutes'
WHERE id = (
  SELECT id FROM jobs
  WHERE state = 'queued'
     OR (state = 'claimed' AND claim_expires_at < now())
  ORDER BY priority ASC, created_at ASC
  FOR UPDATE SKIP LOCKED
  LIMIT 1
)
RETURNING *;
```

## Milestone 3 — directory

`projects.max_concurrent_leases` defaults to 1 (exclusive). Values 2–8 allow extra holders in `chunk_leases` while the chunk row keeps the primary lease. One submission is `validating` at a time. A match releases every other holder.

```sql
CREATE TABLE chunk_leases (
  id                uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  chunk_id          uuid NOT NULL REFERENCES chunks (id) ON DELETE CASCADE,
  user_id           uuid NOT NULL REFERENCES users (id),
  lease_token       uuid NOT NULL,
  lease_expires_at  timestamptz NOT NULL,
  hold_started_at   timestamptz NOT NULL,
  released_at       timestamptz,
  created_at        timestamptz NOT NULL DEFAULT now()
);

CREATE UNIQUE INDEX chunk_leases_token_uidx
  ON chunk_leases (lease_token)
  WHERE released_at IS NULL;

CREATE UNIQUE INDEX chunk_leases_user_active_uidx
  ON chunk_leases (chunk_id, user_id)
  WHERE released_at IS NULL;

CREATE INDEX chunk_leases_chunk_active_idx
  ON chunk_leases (chunk_id)
  WHERE released_at IS NULL;

CREATE TABLE project_events (
  id          uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  project_id  uuid NOT NULL REFERENCES projects (id) ON DELETE CASCADE,
  actor_id    uuid REFERENCES users (id),
  kind        project_event_kind NOT NULL,
  chunk_id    uuid REFERENCES chunks (id) ON DELETE SET NULL,
  subject_id  uuid,
  summary     text NOT NULL,
  created_at  timestamptz NOT NULL DEFAULT now()
);

CREATE INDEX project_events_project_created_idx
  ON project_events (project_id, created_at DESC);

CREATE INDEX project_events_actor_created_idx
  ON project_events (actor_id, created_at DESC)
  WHERE actor_id IS NOT NULL;

CREATE TABLE follows (
  follower_id  uuid NOT NULL REFERENCES users (id) ON DELETE CASCADE,
  project_id   uuid REFERENCES projects (id) ON DELETE CASCADE,
  followee_id  uuid REFERENCES users (id) ON DELETE CASCADE,
  created_at   timestamptz NOT NULL DEFAULT now(),
  CHECK ((project_id IS NULL) <> (followee_id IS NULL)),
  CHECK (followee_id IS NULL OR followee_id <> follower_id)
);

CREATE UNIQUE INDEX follows_project_uidx
  ON follows (follower_id, project_id)
  WHERE project_id IS NOT NULL;

CREATE UNIQUE INDEX follows_user_uidx
  ON follows (follower_id, followee_id)
  WHERE followee_id IS NOT NULL;

CREATE TABLE proposal_regressions (
  id          uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  proposal_id uuid NOT NULL REFERENCES type_proposals (id) ON DELETE CASCADE,
  project_id  uuid NOT NULL REFERENCES projects (id) ON DELETE CASCADE,
  chunk_id    uuid NOT NULL REFERENCES chunks (id) ON DELETE CASCADE,
  caused_by   uuid NOT NULL REFERENCES users (id),
  created_at  timestamptz NOT NULL DEFAULT now(),
  UNIQUE (proposal_id, chunk_id)
);

CREATE INDEX proposal_regressions_caused_by_idx
  ON proposal_regressions (caused_by);
```

Reputation is not stored. It is current matches (`chunks.current_match_id`) minus rows in `proposal_regressions` for that user.

## Milestone 4 — integration

An integration build is not a chunk match. `integrations` is one link of the matched functions in a binary. `integration_units` is the per-chunk byte comparison. `recipe_jobs` recompiles current matches after the owner changes language or flags. Isolated matching still uses `jobs`.

```sql
CREATE TABLE integrations (
  id                uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  project_id        uuid NOT NULL REFERENCES projects (id) ON DELETE CASCADE,
  binary_id         uuid NOT NULL REFERENCES binaries (id) ON DELETE CASCADE,
  status            integration_status NOT NULL DEFAULT 'queued',
  started_by        uuid REFERENCES users (id),
  language          text NOT NULL,
  toolchain         jsonb NOT NULL,
  toolchain_digest  text,                     -- sha256:v2:<cc1 or cc1plus>:<as>:<recipe>
  summary           text NOT NULL DEFAULT '',
  diagnostics       text,
  claimed_at        timestamptz,
  created_at        timestamptz NOT NULL DEFAULT now(),
  finished_at       timestamptz
);

CREATE INDEX integrations_project_created_idx
  ON integrations (project_id, created_at DESC);

CREATE UNIQUE INDEX integrations_one_active
  ON integrations (binary_id)
  WHERE status IN ('queued', 'running');

-- Per-chunk image diff for one integration build. `detail` is the
-- address-range comparison (match line, or the first mismatching bytes).
CREATE TABLE integration_units (
  integration_id  uuid NOT NULL REFERENCES integrations (id) ON DELETE CASCADE,
  chunk_id        uuid NOT NULL REFERENCES chunks (id) ON DELETE CASCADE,
  name            text NOT NULL,
  address         bigint NOT NULL,
  size            integer NOT NULL,
  passed          boolean,
  detail          text NOT NULL DEFAULT '',
  PRIMARY KEY (integration_id, chunk_id)
);

-- Recompile current matches after a language or flag change.
-- Uses job_state. Does not go through `jobs`, so interactive matching stays unchanged.
CREATE TABLE recipe_jobs (
  id                uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  project_id        uuid NOT NULL REFERENCES projects (id) ON DELETE CASCADE,
  chunk_id          uuid NOT NULL REFERENCES chunks (id) ON DELETE CASCADE,
  attempt_id        uuid NOT NULL REFERENCES attempts (id) ON DELETE CASCADE,
  state             job_state NOT NULL DEFAULT 'queued',
  language          text NOT NULL,
  toolchain         jsonb NOT NULL,
  entry_symbol      text NOT NULL,
  original_sha256   bytea NOT NULL REFERENCES blobs (sha256),
  claimed_by        text,
  claim_expires_at  timestamptz,
  result            jsonb,
  created_at        timestamptz NOT NULL DEFAULT now(),
  finished_at       timestamptz
);

CREATE UNIQUE INDEX recipe_jobs_one_active
  ON recipe_jobs (chunk_id)
  WHERE state IN ('queued', 'claimed');

CREATE INDEX recipe_jobs_claim_idx
  ON recipe_jobs (created_at)
  WHERE state = 'queued';
```

## Invariants enforced in the database

1. At most one owner per project.
2. Chunk address ranges inside a binary do not overlap.
3. A chunk has at most one active match.
4. Lease token is unique while set.
5. Attempt idempotency on `(chunk_id, lease_token, source_sha256)`.
6. Lease columns match `chunk_state` (CHECK constraint).
7. Interactive jobs reference an attempt; revalidation jobs reference a proposal.
8. At most one unfinished (`queued` or `claimed`) interactive job per chunk (migration `012`).
9. A chunk's inline-assembly opt-in and a match's inline-assembly mark are never null (migration `013`).

## Invariants enforced in the application (same transaction as the write)

1. Checkout conditional update returns exactly one row or conflict.
2. Heartbeat cannot extend past `hold_started_at + max_hold_hours`.
3. Submit to `validating` only with a matching lease token.
4. Match commit only if chunk is still `validating` for that attempt's lease token, checked under the chunk row lock before the match row is written. A job's result applies once: only the run that moves the job out of `claimed` writes anything.
4a. Submit runs in one transaction under the chunk row lock and only from `leased`.
4b. Checkout runs in one transaction. A per-user, per-project advisory lock guards `max_held_chunks`, and the extra-lease path locks the chunk before counting `chunk_leases` against `max_concurrent_leases`.
4c. A recipe recheck changes only the match for the attempt it was queued for.
5. Members with `fuse_parent_id` set are never leased.
6. Setting an unresolved type moves affected open/stale chunks to `blocked`; clearing moves them back to `open` or `stale` as appropriate.
7. `project_chunk_stats` is recounted after each state change. Concurrent recounts can leave it briefly stale, so the lease sweeper recounts every project with chunk changes in the last two minutes. The counts converge within 30 seconds.
